# v0.1.228 manual test plan

Owner checklist for the v0.1.228 release: agent payments, buying from ME3
sites, background browser jobs, custom Home cards and suggested replies. Run it
on test installations after they update. Tick items as you go and note
failures with what you typed, what ME3 replied, and a screenshot of any card.

## Setup

**Installations**

- **Seller:** `tester.me3.app`, with Stripe in **test mode** (below), one cheap
  product (e.g. €1) and one paid 1:1 booking, published, and listed in the
  ME3 network. Soulink membership is no longer required, but there is no
  settings button yet: opting in is an ME3 Cloud API call
  (`PUT /api/account/network-listing`), tracked as me3-2gdu.16. Until then,
  ask Claude to opt the tester site in, or test buying with a direct
  "Buy [product] from tester.me3.app" request.
- **Buyer:** your main ME3 installation. It pays on the seller's Stripe test
  checkout with a test card, so no real money moves.

**Stripe test mode on the seller (`tester.me3.app`)**

1. In the Stripe Dashboard, switch to **Test mode** or open a **Sandbox**
   (top-left account menu). Use a separate test account if you prefer.
2. Go to **Developers → API keys** and copy the **Secret key** (`sk_test_…`).
   Do not use a live key (`sk_live_…`) on the test installation.
3. On `https://tester.me3.app/settings`, open **Payments → Stripe payments**,
   paste the key into the secret key field (placeholder
   "sk_live_... or sk_test_..."), choose the default currency (EUR) and save.
4. If the page offers both Stripe Connect and the API key, switch customer
   payments to the **API key**. Stripe Connect uses the live platform and
   cannot run in test mode.
5. Publish a product and a paid booking on the tester site and check the site's
   own checkout opens a Stripe page marked **Test mode**.
6. Pay with Stripe's test card **4242 4242 4242 4242**, any future expiry, any
   CVC and postcode. Other test cards: `4000 0000 0000 9995` (declined),
   `4000 0025 0000 3155` (requires authentication).
7. Afterwards, remove the key or replace it before the tester site takes real
   payments. Never paste keys into chat.

**Other notes**

- Web approvals of payments require a sign-in within the last 10 minutes; an
  older session asks you to sign in again. That is expected.
- Browser jobs only appear when the installation has the Browser Run binding.
  If ME3 says it cannot browse, that is why.

## 1. Payments: finish on your device

- [ ] *"I want to buy the Men's Tree Runner in UK 9 from Allbirds UK: https://www.allbirds.co.uk/products/mens-tree-runners"*
      → cart link built from the shop's data (UK 9, £110.00); **Approve payment**
      card with item, total, link and "You pay on your own device".
- [ ] Type **"yes"** in chat instead of tapping Approve → it must **not**
      approve; ME3 points you to the card.
- [ ] Tap **Approve** → after a fresh sign-in or Face ID you get the checkout
      link and instructions; ME3 must **not** say it's paid. Don't buy.
- [ ] *"Show me my payments"* → listed as handed over.
- [ ] Settings → Payments: set the per-payment limit to €20, then *"Buy that
      again"* → refused, citing the limit. Restore the limit after.
- [ ] On the payment, tap **I didn't buy it** → status becomes not paid and the
      30-day total drops back.

## 2. Buying from an ME3 site (buyer installation)

- [ ] *"Find me someone on the ME3 network who offers [the tester service or product]"*
      → the tester site appears with its badges (new seller, Soulink).
- [ ] *"Book the earliest slot next week with [tester]"* or *"Buy [product] from [tester]"*
      → live price and times from the seller; the card says **"Shares your name
      and email with [seller]"**.
- [ ] Approve, open the link, pay with `4242 4242 4242 4242` → the receipt
      appears automatically (no email needed) and a booking lands in the
      calendar. The seller sees the order or booking too.
- [ ] Change the product price on the tester site, then ask to buy it again
      from the earlier proposal → ME3 notices the change and asks again.
- [ ] Approve, then wait more than 15 minutes before opening the link → the
      link refuses and ME3 says the hold expired; no automatic retry.
- [ ] On the tester site (Settings → Payments, agent checkout switch), turn agent checkout off and ask again → ME3 falls
      back to the seller's page link.
- [ ] Pay with the declined card `4000 0000 0000 9995` → no receipt; ME3 does
      not claim success.

## 3. Background browser jobs (read-only)

- [ ] *"Browse retreats.ie and find three yoga retreats in Kerry under €400 next spring"*
      → a background job with a progress card; you can leave Chat; a
      notification and the result arrive when done.
- [ ] *"Stop that"* while it runs → the job stops cleanly.
- [ ] *"Log into my Booking.com account and check my reservations"* → it must
      not type passwords; this version only reads, so it explains it can't sign in.

## 4. Custom Home cards

- [ ] *"Make me a Home card to track my water intake each day"* → a new card on Home.
- [ ] *"I drank 6 glasses today"* → today's value updates.
- [ ] *"Change the card to track 8 glasses as the goal"* → the card updates and
      keeps its history.

## 5. Suggested replies (iOS app)

- [ ] Ask something ME3 answers with a question, e.g. *"Move my 3pm tomorrow"*
      → up to three short tap-replies under the answer, like "Yes, move it".
- [ ] Ask a plain fact question → few or no suggestions.
- [ ] Note any reply that ends noticeably later than before (suggestions can
      add up to 8 seconds before the reply is marked done).
